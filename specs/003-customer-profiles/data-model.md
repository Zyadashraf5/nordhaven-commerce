# Customer Profiles Data Model: Milestone 03

## Scope

This document describes the persistent state owned by the **Customers** module and the invariants that
must hold. It does not resolve HC-DEC-001 through HC-DEC-017. State owned by the Identity and Access
module is unchanged and is described in
[`../002-authentication-authorization/data-model.md`](../002-authentication-authorization/data-model.md).

Ownership rule: the two tables below are owned exclusively by the Customers module and are accessed only
through that module's repositories with the owned Prisma client. No other module may read or write them.

## Persistent Database State

### `customer_profiles`

The storefront-facing data one authenticated customer maintains about themselves. Exactly one row per
customer identity (HC-ASM-M03-005).

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | Primary key, generated by the application-side Prisma default (`uuid(4)`). |
| `user_id` | `uuid` | no | The authenticated customer's identity identifier. **Foreign identifier only** — no foreign key to `users` (research Decision 1). Unique. |
| `display_name` | `text` | yes | Optional display name. Absent means "not provided", never an empty string. |
| `phone` | `text` | yes | Optional contact phone. Format rules that depend on the destination country are deferred to HC-DEC-005. |
| `default_address_id` | `uuid` | yes | The single designated default address, or `NULL` when none is selected. Unique. |
| `created_at` | `timestamp(3)` | no | Defaults to the database `CURRENT_TIMESTAMP`. |
| `updated_at` | `timestamp(3)` | no | Maintained by Prisma on every write. |

Indexes and constraints:

- `customer_profiles_pkey` — primary key on `id`.
- `customer_profiles_user_id_key` — unique index on `user_id`; enforces one profile per customer and makes
  the first-access upsert race-safe.
- `customer_profiles_default_address_id_key` — unique index on `default_address_id`; makes "at most one
  profile may designate this address as default" structural. PostgreSQL permits multiple `NULL` values.
- `customer_profiles_default_address_id_fkey` — foreign key to `customer_addresses(id)`
  `ON DELETE SET NULL ON UPDATE CASCADE`; deleting the default address clears the selection
  (HC-ASM-M03-001).

### `customer_addresses`

One saved shipping address belonging to exactly one customer profile (HC-IAM-004).

| Column | Type | Null | Notes |
| --- | --- | --- | --- |
| `id` | `uuid` | no | Primary key, generated by the application-side Prisma default (`uuid(4)`). |
| `customer_id` | `uuid` | no | Owning profile. Foreign key to `customer_profiles(id)` `ON DELETE CASCADE`. |
| `recipient_name` | `text` | no | Required. |
| `line1` | `text` | no | Required first address line. |
| `line2` | `text` | yes | Optional second address line. |
| `city` | `text` | no | Required. |
| `region` | `text` | yes | Optional state/province/region. |
| `postal_code` | `text` | yes | Optional; mandatory-ness depends on the destination country (HC-DEC-005). |
| `country_code` | `char(2)` | no | ISO 3166-1 alpha-2 **shape** only; normalized to upper case. The supported-country set is not encoded (HC-DEC-005). |
| `phone` | `text` | yes | Optional contact phone for the address. |
| `created_at` | `timestamp(3)` | no | Defaults to the database `CURRENT_TIMESTAMP`. |
| `updated_at` | `timestamp(3)` | no | Maintained by Prisma on every write. |

Indexes and constraints:

- `customer_addresses_pkey` — primary key on `id`.
- `customer_addresses_customer_id_idx` — index on `customer_id`; supports the ownership-scoped listing and
  the profile cascade.
- `customer_addresses_customer_id_fkey` — foreign key to `customer_profiles(id)`
  `ON DELETE CASCADE`; an address cannot outlive its profile.

### Invariants

1. **One profile per identity.** Enforced by the unique index on `customer_profiles.user_id` and the
   first-access upsert.
2. **At most one default per customer.** Enforced structurally by the single
   `customer_profiles.default_address_id` column; two concurrent designations cannot create two defaults.
3. **A default always belongs to its own customer.** Enforced by the service, which verifies ownership in
   the same transaction that writes the reference; the route surface cannot name another customer, so the
   only path to the column goes through an ownership-scoped lookup.
4. **Addresses never outlive their profile.** Enforced by `ON DELETE CASCADE`.
5. **No cross-module table access.** No foreign key or query crosses into Identity and Access storage.

## Runtime Configuration Contract

**No configuration key is added.** The capability is enabled by the accepted accepted configuration
exactly as Milestone 02 left it; `EnvironmentConfiguration` is unchanged. The capability adds no
background job, scheduler, or outbound integration.

## Default Address State Model

| State | Representation | Entered by | Left by |
| --- | --- | --- | --- |
| `NONE` | `default_address_id IS NULL` | A customer with no profile yet, or after the default address is deleted. | Creating the first address, or designating an address as default. |
| `SELECTED` | `default_address_id = <address of this customer>` | Creating the first address (HC-ASM-M03-001), or an explicit designation. | Designating another address, or deleting the currently selected address (returns to `NONE`). |

Transitions are deliberately total: every address belongs to exactly one profile, deleting an address
either clears the selection (when it was selected) or changes nothing, and deleting a profile removes its
addresses and the profile together.

## Error Contract

One code is added to the closed `AppErrorCode` union. The full customer-facing failure surface is:

| Situation | Status | Code | Disclosure |
| --- | --- | --- | --- |
| Missing or unusable session credential | `401` | `UNAUTHENTICATED` | None. |
| Authenticated but not a customer (administrator) | `403` | `FORBIDDEN` | None; the denial is audited through the accepted authorization-audit port. |
| Malformed path or body value (including a non-UUID address identifier) | `400` | `VALIDATION_ERROR` | Field path and a constant message only; never the submitted value. |
| Address not owned by the principal, unknown, or already deleted | `404` | `ADDRESS_NOT_FOUND` | Identical for all three cases. |
| Rate limit exceeded | `429` | `RATE_LIMITED` | Bounded, with `Retry-After`. |
| Unexpected failure | `500` | `INTERNAL_ERROR` | None. |
| Instance not ready | `503` | `SERVICE_UNAVAILABLE` | None, with `Retry-After`. |

No code discloses account existence, and no customer code is added that describes another customer's
resource.

## Test Database Ownership

Both tables belong to the Customers module and are exercised against the existing isolated
`nordhaven_integration` and `nordhaven_e2e` databases, guarded by the accepted `assertSafeTestDatabase`
check. The integration and E2E suites reset `customer_addresses` before `customer_profiles` so teardown
stays valid regardless of the cascade rules, and the accepted identity reset continues to run first so a
suite can exercise the accepted identity flows in the same database.

## Migration

| Migration | Contents | Reversibility |
| --- | --- | --- |
| `<timestamp>_customer_profiles` (created with `prisma:migrate:create --name customer_profiles`) | Creates `customer_profiles`, `customer_addresses`, their primary keys, indexes, and the two intra-module foreign keys. | Additive create-only: no existing table, column, or index is altered or dropped. Reverting consists of dropping the two new tables, which destructive tooling is prohibited from doing automatically. |

Application startup never migrates. `prisma migrate reset`, `prisma db push`, and volume or database
deletion remain prohibited.
