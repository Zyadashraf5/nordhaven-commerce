# Identity and Access Data Model: Milestone 02

## Scope

This document defines the persistent and runtime structures owned by the Identity and Access module.
Every table listed here is owned exclusively by that module; no other module may read from or write to
it directly. No commerce entity is introduced. Customer profile data, saved addresses, wishlists,
account-deletion and export workflows, email verification state, and real notification delivery remain
out of scope and are tracked by HC-DEC-002, HC-DEC-003, and HC-DEC-014.

The schema is introduced by one additive, reviewed migration named `identity_access`. No existing
table or migration is modified.

## Persistent Database State

### `users`

**Owner**: Identity and Access module. **Purpose**: The authenticated principal record for both
customers and administrators.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | uuid | No | Primary key, generated by the application |
| `email` | text | No | Unique, stored normalized (trimmed, lower-cased); the only sign-in identifier |
| `password_hash` | text | No | Versioned `scrypt` representation; never reversible; never logged |
| `role` | `user_role` | No | `CUSTOMER` by default; `ADMIN` only through the provisioning path |
| `failed_login_attempts` | integer | No | Default `0`; reset on successful sign-in |
| `locked_until` | timestamp | Yes | Null when not locked; expiry is enforced on read |
| `password_changed_at` | timestamp | Yes | Set whenever the password changes |
| `created_at` | timestamp | No | Default `now()` |
| `updated_at` | timestamp | No | Updated on every write |

**Rules**:

- Uniqueness is enforced by the database, so concurrent duplicate registration cannot create two rows.
- Email verification state is deliberately absent (HC-DEC-002 open); no response may claim an address
  is verified.
- A locked account is not a distinct API outcome: lockout is applied internally and returns the same
  result as an invalid credential.
- `password_hash` and `email` never appear in logs or security-event detail.

### `sessions`

**Owner**: Identity and Access module. **Purpose**: One authenticated device/client session.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | uuid | No | Primary key; safe to expose as a session identifier |
| `user_id` | uuid | No | Foreign key to `users`; delete cascades |
| `token_hash` | text | No | Unique SHA-256 of the session credential; the credential itself is never stored |
| `client_label` | text | Yes | Sanitized, truncated client description derived from `User-Agent`; no address is stored |
| `created_at` | timestamp | No | Default `now()` |
| `last_used_at` | timestamp | No | Default `now()`; refreshed at most once per minute per session |
| `expires_at` | timestamp | No | Absolute expiry |
| `revoked_at` | timestamp | Yes | Set when revoked |
| `revoked_reason` | text | Yes | Closed reason set: `logout`, `logout_all`, `password_reset`, `password_change` |

**Rules**:

- A session is valid only when `revoked_at` is null, `expires_at` is in the future, and
  `last_used_at + idle_ttl` is in the future.
- Sessions for one account are independent; revoking one never affects another, satisfying HC-IAM-005.
- Only `id`, `created_at`, `last_used_at`, `expires_at`, `client_label`, and a computed current-session
  flag are ever returned to a client.

### `identity_tokens`

**Owner**: Identity and Access module. **Purpose**: Single-use tokens for password reset and
administrator MFA challenges.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | uuid | No | Primary key; not exposed |
| `user_id` | uuid | No | Foreign key to `users`; delete cascades |
| `purpose` | `identity_token_purpose` | No | `PASSWORD_RESET`, `MFA_ENROLLMENT`, or `MFA_VERIFICATION` |
| `token_hash` | text | No | Unique SHA-256 of the token; the token itself is never stored |
| `created_at` | timestamp | No | Default `now()` |
| `expires_at` | timestamp | No | Purpose-specific lifetime |
| `consumed_at` | timestamp | Yes | Set on first successful use; a consumed token can never be reused |
| `invalidated_at` | timestamp | Yes | Set when superseded by a newer token of the same purpose |

**Rules**:

- A token is usable only when it is unconsumed, unexpired, and not invalidated.
- Requesting a password reset invalidates every outstanding `PASSWORD_RESET` token for that user.
- Purpose is verified on use, so a token can never be replayed into a different flow.

### `admin_mfa_credentials`

**Owner**: Identity and Access module. **Purpose**: The administrator authenticator factor.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `user_id` | uuid | No | Primary key and foreign key to `users`; delete cascades |
| `secret_ciphertext` | text | No | AES-256-GCM `v1:<iv>:<tag>:<ciphertext>`; never returned after enrollment |
| `created_at` | timestamp | No | Default `now()` |
| `confirmed_at` | timestamp | Yes | Null until a correct code confirms enrollment |
| `last_accepted_step` | integer | Yes | Highest accepted TOTP time step; prevents replay inside the window |

**Rules**:

- Only a `confirmed_at` credential grants administrative authentication.
- Every code verification compares the derived step with `last_accepted_step` and rejects any step
  that is not strictly greater.
- The secret is readable only by the MFA service after decryption with the configured key.

### `admin_mfa_recovery_codes`

**Owner**: Identity and Access module. **Purpose**: Single-use recovery when the authenticator is
unavailable.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | uuid | No | Primary key |
| `user_id` | uuid | No | Foreign key to `users`; delete cascades |
| `code_hash` | text | No | Unique SHA-256 of the recovery code |
| `created_at` | timestamp | No | Default `now()` |
| `used_at` | timestamp | Yes | Set on first successful use |

**Rules**:

- Recovery codes are returned as plaintext exactly once at enrollment confirmation.
- A code can be used once; a second attempt fails with the same safe verification error.
- Codes are never logged and never returned again.

### `security_events`

**Owner**: Identity and Access module. **Purpose**: Durable, non-sensitive audit facts for
security-relevant and privileged events.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | uuid | No | Primary key |
| `event_type` | `security_event_type` | No | Closed enumeration (below) |
| `outcome` | `security_event_outcome` | No | `SUCCESS`, `FAILURE`, or `DENIED` |
| `actor_user_id` | uuid | Yes | The acting principal when known |
| `actor_role` | `user_role` | Yes | The acting role when known |
| `correlation_id` | uuid | No | The request correlation identifier |
| `detail` | json | Yes | Closed, non-sensitive shape only; never credentials or personal data |
| `created_at` | timestamp | No | Default `now()` |

**Event types**: `USER_REGISTERED`, `REGISTRATION_REJECTED`, `LOGIN_SUCCEEDED`, `LOGIN_FAILED`,
`ACCOUNT_LOCKED`, `MFA_ENROLLMENT_STARTED`, `MFA_ENROLLED`, `MFA_VERIFIED`, `MFA_VERIFICATION_FAILED`,
`RECOVERY_CODE_USED`, `PASSWORD_RESET_REQUESTED`, `PASSWORD_RESET_COMPLETED`, `PASSWORD_CHANGED`,
`SESSION_REVOKED`, `SESSIONS_REVOKED`, `SESSION_REJECTED`, `ADMIN_ACCESS_DENIED`,
`ADMIN_ACCESS_GRANTED`, `NOTIFICATION_DELIVERY_SKIPPED`.

**Rules**:

- A failure to persist an event is caught and logged as a non-sensitive failure; it never changes the
  authentication or authorization outcome.
- `detail` never contains a password, session credential, MFA secret or code, recovery code or token,
  authorization header, email address, or connection string.
- An additional all-sessions-revoked event (`SESSIONS_REVOKED`) records a group revocation without
  writing one row per session.

## Runtime Configuration Contract

### EnvironmentConfiguration (Milestone 02 additions)

| Field | Type | Required | Validation | Sensitive |
| --- | --- | --- | --- | --- |
| `authEncryptionKey` | base64 string | Yes | Decodes to exactly 32 bytes | Yes |
| `authSessionAbsoluteTtlSeconds` | integer | Default 2592000 | 300 to 7776000 | No |
| `authSessionIdleTtlSeconds` | integer | Default 604800 | 300 to 2592000 | No |
| `authMaxFailedAttempts` | integer | Default 10 | 3 to 100 | No |
| `authLockoutSeconds` | integer | Default 900 | 30 to 86400 | No |
| `authPasswordResetTtlSeconds` | integer | Default 1800 | 300 to 86400 | No |
| `authMfaIssuer` | string | Default `Nordhaven Commerce` | 1 to 64 characters, no control characters | No |
| `authNotificationTransport` | enum | Default `none` | `none`, `file`, `memory`; `file` rejected in production | No |

**Validation rules**:

- The encryption key is never serialized, echoed, or included in diagnostics; a violation names only
  the key.
- The idle lifetime must not exceed the absolute lifetime.
- Selecting the file transport while `NODE_ENV=production` is a configuration error.

## Session and Token State Model

### Session states

| State | Condition | Authentication outcome |
| --- | --- | --- |
| `ACTIVE` | Not revoked, absolute expiry in the future, idle expiry in the future | Accepted |
| `IDLE_EXPIRED` | `last_used_at + idle_ttl` has passed | Rejected as unauthenticated; recorded |
| `EXPIRED` | Absolute expiry has passed | Rejected as unauthenticated; recorded |
| `REVOKED` | `revoked_at` is set | Rejected as unauthenticated; recorded |

```text
ACTIVE --idle timeout--------> IDLE_EXPIRED
ACTIVE --absolute timeout----> EXPIRED
ACTIVE --logout/revocation---> REVOKED
ACTIVE --password reset------> REVOKED (all sessions)
```

### Identity token states

| State | Condition | Outcome |
| --- | --- | --- |
| `USABLE` | Unconsumed, unexpired, not invalidated, purpose matches | Accepted once |
| `CONSUMED` | `consumed_at` set | Rejected |
| `EXPIRED` | Past `expires_at` | Rejected |
| `INVALIDATED` | Superseded by a newer token of the same purpose | Rejected |

### Administrator MFA states

| State | Condition | Sign-in outcome |
| --- | --- | --- |
| `NOT_ENROLLED` | No credential row | `202` with an enrollment challenge |
| `PENDING_CONFIRMATION` | Credential exists, `confirmed_at` null | No administrative session; enrollment path only |
| `ENROLLED` | `confirmed_at` set | `202` with a verification challenge, then a session on success |

## Error Contract

`AppError` carries one of the following codes. The set is closed at the type level, so an unreviewed
code is a compile error. Messages are constant, short, and non-sensitive.

| Status | Code | When |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Boundary validation failed (existing behavior) |
| 400 | `INVALID_RECOVERY_TOKEN` | Reset token is unknown, consumed, expired, or invalidated |
| 401 | `UNAUTHENTICATED` | No session credential was presented or it is not usable |
| 401 | `INVALID_CREDENTIALS` | Wrong password, unknown account, or locked account |
| 401 | `INVALID_CHALLENGE` | MFA challenge token is unknown, consumed, expired, or invalidated |
| 401 | `INVALID_MFA_CODE` | TOTP code or recovery code is wrong, expired, or replayed |
| 403 | `FORBIDDEN` | Authenticated principal lacks the required role |
| 404 | `SESSION_NOT_FOUND` | Session identifier does not belong to the principal |
| 409 | `REGISTRATION_NOT_ALLOWED` | Email address is already registered |
| 429 | `RATE_LIMITED` | Client or account rate limit exceeded; includes `Retry-After` |
| 503 | `SERVICE_UNAVAILABLE` | Instance is not ready (existing behavior) |
| 500 | `INTERNAL_ERROR` | Unclassified failure (existing behavior) |

**Rules**:

- `INVALID_CREDENTIALS` and `UNAUTHENTICATED` never distinguish an unknown account from a wrong
  credential, and a locked account returns exactly `INVALID_CREDENTIALS`.
- `RATE_LIMITED` depends only on the client key, so it discloses no account existence.
- No code and no message may include a submitted value, an internal identifier, or a database error.
- Responses that carry a session credential set `Cache-Control: no-store`.

## Test Database Ownership

| Database | Owner | Allowed use |
| --- | --- | --- |
| `nordhaven` | Local developer | Manual development; the additive migration is applied here first |
| `nordhaven_integration` | Integration suite | Identity persistence, constraints, lifecycle, lockout durability |
| `nordhaven_e2e` | E2E/process suite | Full identity HTTP journeys and contract validation |

Test setup MUST validate `NODE_ENV=test`, host allowlisting, and the exact database suffix before any
cleanup. Suites clean only their own identity rows, in foreign-key-safe order
(`security_events` -> `admin_mfa_recovery_codes` -> `admin_mfa_credentials` -> `identity_tokens` ->
`sessions` -> `users`).
